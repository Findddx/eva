# eva

**围绕你的工作站构建个人推理。** · [English](README.md)

eva 是面向个人工作站的本地推理框架，将 GPU 显存、RAM 和 NVMe 组织成分层系统，让显存装不下的大型混合专家模型也能完整运行。首个后端聚焦 DeepSeek、EXL3 量化专家和完整 Engram。

一台个人工作站会反复服务同一个人的项目、工具和工作方式。这些重复需求，为判断哪些专家和上下文值得留在近处提供了线索。我们的目标是把真实使用中的线索转化为更合适的内存放置和更少的数据搬运，让本地 AI 随着熟悉你的工作而逐渐变得顺手。

## 核心思路

把有用的专家留在近处，让它们随着工作负载变化动态进入和退出，减少权重搬运。再结合可复用的上下文与更细的专家存储，充分利用个人工作站。

- **面向个人工作负载的驻留：** 从本地路由样本中提取偏好，并与当前请求的需求协调。
- **常驻上下文：** 跨请求复用兼容的 KV 和前缀状态，明确所有权、淘汰和失效条件。
- **更细的专家访问：** 探索量化专家分片与路由感知调度，同时保留清楚的数值约定。

现有分层执行与路由画像原型是起点。跨请求上下文复用和更细专家分片是下一步，长期收益将通过真实、连续的工作负载验证。

## 框架包含什么

- GPU 热点与动态专家缓存、锁页 RAM、对齐存储记录和按需数据传输。
- 由目标模型验证的历史与 prompt 提案，以及明确的接受、回滚和状态所有权。
- 合作式量化 MoE 内核、规范批量运算、CUDA Graph 和共享工作区。
- 常驻模型 worker、流式 HTTP API，以及支持实时输出和请求计时的交互式评测客户端。

当前数值路径在量化执行周围使用 BF16 残差与 FP32 归一化，并明确管理状态与内存所有权。

## 实测及其范围

| 工作负载 | 已记录解码速度 | 范围 |
| --- | ---: | --- |
| 普通代码与科研代码单题 | 约 **24–25 tokens/s** | 较早的 Half 目标与小窗口草稿路径 |
| 对给定长代码做窄范围编辑 | 约 **110 tokens/s** | BF16 残差目标，大量复用 prompt 内容 |

这些是特定任务的解码结果，加载、prefill 与校验成本另计。两条路径采用不同的数值配置。详见[测试范围](BENCHMARKS.md)。

## 开始使用

先启动[模型服务](GETTING_STARTED.md)，再流式发送一个问题：

```bash
python client.py --url http://127.0.0.1:8000 --prompt "Write a Python function that merges two sorted lists."
```

运行 `python client.py` 进入交互模式，也可以使用[示例提示词集](examples/prompts.json)比较自己的工作负载。
